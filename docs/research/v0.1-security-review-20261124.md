# v0.1 pre-release security review (2026-11-24)

The question (coordinator, 2026-11-24): before v0.1, where can Nacre's privilege
boundaries be crossed? Covered: the daemon socket, helper leases, every root path, the
installers, tools.launch, clipboard history, network secrets, and the AI chat and Brain.

**Short answer:**
- No Critical or High findings.
- Nothing lets a remote network attacker or a web page in.
- Nothing reaches root without the admin password.
- Five Medium findings:
  - Two are in the Brain web window's login (C1, C2): another local user can take over
    a 30-day Brain session.
  - Two are in the login-theme installer (B1, B2): root runs a script, and copies theme
    files, from the user's home folder.
  - One is a setting bypass (C3): Codex ignores the "AI full access" switch when it is off.
- The one cheap robustness fix worth landing before v0.1 is A1 + A2. One same-user
  `mkfifo` hangs the daemon, then stops it restarting for the rest of the session.

## Method and threat model

- Read-only code review of nacre `origin/main` at `7626dd4b9`. Nothing was built, run or
  probed on a live system. Three Opus reviewers read the code (A: socket and leases; B: root
  paths and installers; C: features, AI and Brain).
- The Clasp lead then re-read the lines behind every Medium finding and A1 + A2, marked
  *lead-verified* below. The other findings are as reported, with the reviewer's own
  confidence.
- File:line references are at `7626dd4b9`.
- Attackers ranked: another local user account; a sandboxed app of the same user
  (Flatpak/bubblewrap); malicious content (files, theme folders, clipboard data, AI-tool
  output); anything that reaches root.
- An unsandboxed process already running as the same user is mostly trusted, since it can
  ptrace. Same-user-only issues are rated Low or Info, unless they cross into root, defeat a
  boundary the code claims to enforce, or leak secrets to a shared or persistent place.

### C1 — Medium — Brain login token on the browser's command line (lead-verified)

- **Where:**
  - `brain_auth.rs:220-224` builds `http://127.0.0.1:PORT/#nacre-bootstrap=<token>`.
  - `brain_launch.rs:249` passes it as `--app=…`, launched from `:432-434` and `:538-539`.
  - `process.rs:173-200` runs it through `systemd-run … <browser> --app=URL`.
- **Attacker:** another local user. `/proc/<pid>/cmdline` is readable by every user unless
  `/proc` is mounted with `hidepid`, and nothing in the repo sets that.
- **Path:**
  1. The victim opens the Brain.
  2. The attacker polls `/proc/*/cmdline` and reads the token, which is single-use and
     lives 300 s.
  3. Before the browser runs its page script, the attacker POSTs `/api/bootstrap` with a
     forged `Origin`, `Sec-Fetch-Site` and JSON content type. These checks
     (`brain_http.rs:241-250`) are header checks, and curl can set those headers.
  4. `consume_bootstrap` (`brain_auth.rs:113-158`) returns the persistent session: the
     bearer and the cookie.
  5. With them, the attacker gets every `/api/*` route (vault read, Ask, actions) for up
     to 30 days (`SESSION_TTL`, `brain_auth.rs:13`).
- **Fix:** keep the token off the command line. Either bring back a private 0600 handoff
  file, as the Python reference `brain/control.py:784-816` did before `f307042ac`, or
  accept only loopback peers owned by `getuid()` (look up the peer port in
  `/proc/net/tcp`). The second also closes C2 for other users.
- **Confidence:** the code path is verified. The race (beating the browser's first
  script) is inferred, not measured.

### C2 — Medium — Fixed-port squatting captures the Brain session (lead-verified for session reuse)

- **Where:**
  - The port is fixed at 17843 (`brain_web.rs:67-70`).
  - The server exits after 300 s idle (`:1807-1811`) or when its binary changes
    (`brain_http.rs:130-131`, `:184`).
  - `BrowserAuth::open` reuses the stored session until it expires
    (`brain_auth.rs:47`, `active_session` `:227-240`).
  - The open window sends the bearer on every same-origin fetch (`brain_web.rs:33`) and
    polls every second (`app.js:2612-2614`).
- **Attacker:** another local user, or a Flatpak app with network access (it shares the
  host loopback).
- **Path:**
  1. The port frees up after an idle exit, an update or a crash.
  2. The attacker binds 127.0.0.1:17843.
  3. Within a second, the already-open window sends it the bearer and the cookie. The
     attacker can also serve its own script at that origin.
  4. The attacker lets go of the port. The real server restarts with the same session,
     and the stolen credentials stay valid for up to 30 days.
- **Not affected:** the launcher's readiness HMAC (`brain_launch.rs:490-532`) refuses a
  squatter, so a fresh launch does not leak.
- **Fix:** mint a fresh cookie and bearer on every `serve` start in `BrowserAuth::open`.
  The existing re-login of the open window (`brain_web.rs:1812-1816`) absorbs the change.
  Land C1's fix first, since each re-login otherwise puts a new token on a command line.
- **Confidence:** the code path is verified. The timing window is inferred.

### B1 — Medium — `login.install_theme` pkexecs a script from the user's home folder (lead-verified)

- **Where:**
  - `login_theme.rs:49` takes `paths.assets()/login-install.py`, which is
    `~/.local/share/nacre/shell/tools`, copied there by `nacre/shell-tools/install.py:960-965`.
  - `:51-56` takes the theme folder from beside it.
  - `:142-153` runs `pkexec /usr/bin/python3 <that script> --user U --theme <that dir>`.
- **Attacker:** a same-user process or a Flatpak with home access. The crossing is the
  admin password. It is entered at a real prompt the user started, so it is a convincing
  root takeover, not a bypass.
- **Path:**
  1. The attacker overwrites `login-install.py`. On a packaged install, the attacker also
     creates the theme files so the Settings button appears (`login_theme.rs:83`).
  2. The user clicks Install and authenticates.
  3. The attacker's Python runs as root.
- **Fix:** ship `login-install.py` and the theme root-owned in the package (for example
  `/usr/lib/nacre/` and `/usr/share/nacre/login/`). pkexec only those absolute paths, and
  drop `--theme`.

### B2 — Medium — The root-side theme copy follows symlinks (lead-verified)

- **Where:** `nacre/shell-tools/login-install.py:83-85` checks the files with `is_file()`,
  which follows links. `:56-60` then `shutil.copyfile(source/name, target)` (also following
  links) and `chmod 0644`.
- **Attacker:** as B1. This stays open if only the script moves and the theme still
  comes from the home folder.
- **Path:** any of these follows from a link or file the attacker plants:
  - `theme.conf -> /etc/shadow` is copied, world-readable, to
    `/usr/share/sddm/themes/nacre/`.
  - Attacker QML in `Main.qml` runs in SDDM on the login screen as the sddm user, and sees
    every user's typed password.
  - A link to `/dev/zero` fills `/usr`.
- **Fix:** B1's root-owned theme folder. If a theme argument must stay, open with
  `O_NOFOLLOW`, require a root-owned regular file, and cap the size.

### C3 — Medium — Codex ignores the AI full-access setting (lead-verified)

- **Where:**
  - `ai_chat.rs:815` writes top-level `sandbox_mode = "danger-full-access"` and
    `approval_policy = "never"` into Codex's `config.toml`. `ai/install.py:336-345` does
    this with `CODEX_HOME=~/.codex`, so it changes the user's global Codex default.
  - The same flags are hard-coded at `ai_chat.rs:937`, `ai_wrappers.rs:721-722` and
    `desktop_extras.rs:766-767`.
  - By contrast, Claude and the dashboard honour `ai_core::full_access()`
    (`ai_claude.rs:1475,1491`, `ai_dashboard.rs:1456,1694`).
- **Attacker:** malicious content (a web page, repo, note or tool output) injects
  instructions into a Codex session. The user turned full access off, so they expect an
  approval prompt. Codex runs the commands anyway.
- **Fix:** gate those four places on `ai_core::full_access()`, as `ai_dashboard` does, and
  stop writing the global top-level keys from the installer.
- **Note:** the owner's own setup is deliberately full access and must not change. This
  finding is about the default for other users when the switch is off.

### A1 — Low — A FIFO packet hangs the whole daemon (lead-verified)

- **Where:**
  - `crates/nacre-helper/src/daemon/helpers.rs:72-75` opens the packet read-only with
    `O_NOFOLLOW` only. On a FIFO, `open()` blocks before the `is_file()` check. The
    release path at `:95` is the same.
  - The daemon runs a single current-thread runtime (`daemon.rs:891-896`, as reported).
    Every client and the watchdog keepalive stall until `WatchdogSec=20` kills it.
- **Attacker:** any same-user process that can reach `daemon.sock`, including a sandbox
  granted that directory (A4).
- **Path:** `helper.transfer {}`, then `mkfifo <dir>/packet-x`, then
  `helper.execute {"file":"packet-x"}`.
- **Fix:** add `O_NONBLOCK` (then `is_file()` rejects the FIFO). Do the same at
  `serve_bridge.rs:159` and `crashes.rs:40`. `brain_auth.rs:288` already does it.

### A2 — Low — One bad stale lease file stops the daemon for the session (lead-verified)

- **Where:** `helpers.rs:343-361` returns an error for any stale packet that is not a
  regular 0600 file. `daemon.rs:110` (`helpers::cleanup()?`) runs at every start, safe mode
  included.
- **Path:**
  1. A1's FIFO survives the watchdog kill. A client-written 0644 packet has the same
     effect.
  2. Every restart then fails.
  3. With `Restart=on-failure` and `RestartSec=0.5`, systemd's default start limit trips,
     and the desktop link stays down until logout.
- **Fix:** keep the directory-level checks. Drop the per-file checks, because
  `remove_dir_all` does not follow symlinks. Log and continue instead of returning the
  error.

### A3 — Low — brain.sock skips daemon.sock's guards

- **Where:** `brain_socket.rs:145-150` creates `$XDG_RUNTIME_DIR/nacre` with the umask
  (0755) and unlinks an existing path unchecked. The shell's client
  (`crates/nacre-shell/src/brain.rs:398`) checks no peer UID, which contradicts
  `protocol.md:30-31`.
- **Effect:** if the Brain worker creates the folder first, the daemon (`socket.rs:91`)
  and the shell refuse it for the session. Under logind's private 0700
  `/run/user/UID`, this is a denial of service only.
- **Fix:** create the folder 0700 (reuse `socket::directory`), and check
  `peer_cred().uid()` in the client.

### B3 — Low — The greeter's `background` is unchecked

- **Where:** `login-install.py:52-55,61-63` links `theme.conf.user` to the user-owned
  `/var/lib/nacre/login/appearance`. `nacre/login/Main.qml:62` uses `config.background`
  unchecked; the colours are checked at `:37-40`.
- **Effect:** the login screen every user sees can load any file the sddm user can read,
  or possibly a remote URL as a beacon. Qt's network fetch under SDDM was not confirmed.
- **Fix:** accept only `file:///var/lib/nacre/login/appearance/<name>.png`.

### B4 — Low — `pkexec` and its targets come from PATH

- **Where:** `login_theme.rs:61`, `tools_launch.rs:95-96`, `software_actions.rs:389,421`,
  `menu_registry.rs:68-69`, `aur_review.rs:421-431`, `tools/package_transaction.py:50`,
  `nacre/shell-tools/updates.sh:65`.
- **Effect:** a same-user PATH entry (`~/.local/bin`, the systemd user environment) can
  fake the password prompt, or swap the program that gets authorised.
- **Fix:** call `/usr/bin/pkexec` and `/usr/bin/<tool>`.

### C4 — Low — Clipboard history stores first, then checks "sensitive" (lead-verified)

- **Where:** `desktop_extras.rs:197-206` runs `cliphist store` before the
  `CLIPBOARD_STATE=sensitive` early return.
- **Effect:** keeping password-manager copies out of history depends on cliphist's own
  handling, and no minimum cliphist version is pinned. Also:
  - Up to 200 characters of each entry go out on the `clipboard` daemon topic
    (`:280-296`). The comment at `clipboard.rs:1-2` saying content never leaves cliphist is
    wrong.
  - History lives in plain text in `~/.cache/cliphist/db` for 7 days by default, and
    recording cannot be turned off.
- **Fix:** move the sensitive check above `cliphist store` (3 lines).

### Info

- **A4 (Release, docs):** the socket checks only that the peer is the same user
  (`session.rs:408`, `fast.rs:103`). A sandbox granted `xdg-run/nacre` gets the whole API
  (`helper.execute`, `settings.set`, `network.connect`). Document "never grant
  `xdg-run/nacre`".
- **A5 (Platform):** `dashboard_media.rs:254-260` checks the 8 MB cap from `metadata().len()`
  before reading; that length is 0 for FIFOs and `/dev/zero`. Only a same-user socket
  client can pass the path. Open, `fstat`, require a regular file and read with `take()`.
- **A6 (Platform):**
  - The fast lane has no total read deadline (`fast.rs:86,227-233`).
  - It replies `{"changed":true}` to any method (`:177-184`).
  - `add_client` runs before hello (`session.rs:416` vs `:434`).
- **A7 (Platform):** `socket.rs:72,96` trusts parent directories owned by the owner of
  `/`. Inside a user namespace that is the overflow UID. The worst case is a denial of
  service.
- **B5 (Release):** `login-install.py` never sets `os.umask(0o022)`, so a loose caller
  umask could leave new root folders writable by everyone. Whether pkexec resets the
  umask was not confirmed.
- **B6 (Shell):** `nacre-helper menu-backend install PKG` adds `--skipreview`
  (`main.rs:633-647`, `menu_registry.rs:53-56`). The UI path applies the review policy
  (`aur_review.rs:688-692`). The owner's own `--skipreview` stays; only this command-line
  route should go through `package_install`.
- **B7 (Release):**
  - `packaging/arch/bootstrap.sh:39-52` checks the key file before `pacman-key --add`
    reads it, so a same-user process could swap it in between.
  - The user-namespace re-run through `systemd-run --user` adds nothing new.

## Checked and sound

- **Daemon socket:**
  - Every path component is checked with lstat, and symlinks are refused. The folder is
    created 0700, must be ours and exactly 0700, and is never chmodded. The socket is
    bound inside it and set 0600 (`socket.rs:69-95,186-189`).
  - The lock file is `O_NOFOLLOW` and must be ours, with one link, 0600 and flocked
    (`:127-144`).
  - Socket activation checks `LISTEN_PID`, the path and the endpoint (`:145-162`).
  - The peer UID is checked on every accepted connection before reading, on the main,
    fast and brain sockets.
  - `NACRE_DAEMON_SOCKET` must be absolute, with no `.` or `..`, and it never disables a
    check (`socket.rs:50-68`).
- **Helper leases:**
  - One per connection, in a 0700 folder.
  - Packet names match `packet-[A-Za-z0-9_-]{…96}`.
  - Files are opened first, then checked on the handle (`O_NOFOLLOW`, regular file, ours,
    0600, one link).
  - The size cap is enforced both up front and while reading.
  - At most 128 packets; the folder is removed on disconnect.
  - `helper.execute` has a 6-tool allowlist with fixed argument shapes. Its worker is
    `/proc/self/exe`, with `LISTEN_*` and `NOTIFY` removed and a 10 s deadline.
- **Root paths:**
  - No polkit `.policy`/`.rules` or sudoers files are shipped, so pkexec asks for the
    admin password every time.
  - Time zone and NTP go only through timedated D-Bus, with the zone validated
    (`time_settings.rs:192-234`).
  - Display apply and its rollback timer are user-level only.
  - Fixed-command root actions are allowlisted, and package names are validated and
    passed after `--`.
- **Installers:**
  - `install.sh` hands off to `tools/manage.py`.
  - `ai/` and `brain/` installers use no sudo.
  - Downloads are pinned by SHA-256.
  - `bootstrap.sh` refuses root, pins one key fingerprint, uses
    `SigLevel Required DatabaseRequired TrustedOnly`, and backs up `pacman.conf`.
  - There is no `curl | sh`, and uninstall only prints a `pacman -Rns` hint.
- **tools.launch** is a closed set:
  - The `Tool` enum is `deny_unknown_fields`, each id maps to a fixed argv, and launches go
    through `systemd-run` with an argv vector.
  - No `sh -c`, desktop-file Exec, env or cwd comes from the caller.
  - Tests reject extra args and unknown tools.
- **Network secrets:**
  - `Debug` prints `<redacted>`, and error strings are fixed text.
  - The secret only travels in NetworkManager's `AddAndActivateConnection2` settings.
  - The nmcli fallback uses `--ask`, never an argument.
  - The shell clears the secret store after use and keeps it out of saved state.
- **Brain HTTP:**
  - Loopback only, with an exact Host allowlist against DNS rebinding.
  - POST needs cookie, bearer, Origin and JSON. No CORS, and a strict CSP.
  - Secrets are compared in constant time, and auth files are 0600 `O_NOFOLLOW`.
  - `/api/action` is a closed list, and `note_path` blocks traversal and links.
  - Ask runs `claude -p --tools ""` on stdin, after a secret scan.
- **AI credentials** are never copied, logged or put on command lines. Only
  `CLAUDE_CONFIG_DIR` and `CODEX_HOME` are set.

## Not covered

- The shell's own Bead IPC sockets and the daemon's D-Bus services (notifications, tray,
  MPRIS).
- The orient decoder (`deps/orient`, not checked out).
- cliphist and wl-clipboard internals; the `brain_git` sync secret scan.
- The installed system's polkit files and `/proc` mount options (live, off limits).
- Every timing claim (C1, C2, A1) is inferred from the code, not measured.
