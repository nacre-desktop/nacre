| --- | --- | --- | --- | --- |

| `colors.preview` (A2) | `{request}` (the QML request object) | `{id, request, name, image, thumbnail, frames, favorite, otherCoverage, imageColors[{hex,coverage}], colours{role:hex}, audit{textPasses,minimumTextContrast,warnings,text[],simulated{protan,deutan,tritan}}, comparisons[{personality,colours,minimumContrast}]}` | 60 s | `colors serve` / `preview` |

Schemas `protocol/schema/colors-*.json`, types `protocol/luau/colors.d.luau`, golden `protocol/fixtures/colors.jsonl`
(generated by `cargo run -p nacre-protocol --example export`, never edited).

Behaviour.
- The engine runs as a child of the daemon's executable (`nice -n 10`, `NOTIFY_SOCKET` removed, fixed argv); the
  request only reaches it as a JSON line on stdin. The helper writes the `colors` store through the daemon's provider
  route (as the QML did), so apply updates `settings.store.colors.lastApplied` and `wallpaper.active` as in A3.
  `colors.apply` sets `NACRE_PRESENTATION_STREAM=0`: the topics carry the result, nothing is streamed.
- Preview: one at a time, newest wins. A newer `colors.preview` cancels the running or waiting older one (child killed,
  older call fails `busy`, retry true); Bead already drops stale replies. Refusals are `validation` with the engine's
  first error line, at most 240 characters.
- Actions (`apply`, `export`, `set_target`) share one lane (`busy` while another runs) and are not cancelled by a caller
  deadline; the child stops at 55 s. `set_target` ids must name a target of the manifest.
- `simulated` uses `protan`/`deutan`/`tritan` (the engine's `protanopia`/`deuteranopia`/`tritanopia` renamed, as
  B0060 reads them). `comparisons` is empty unless the request has `compare: true`. `minimumContrast` is an extra field.
- Advertised only with the settings service and never in safe mode (`permission_denied`, `dispatched:false`).

## A5 cache images

Folders `$XDG_CACHE_HOME/nacre/shell/colors-thumbs/` (list thumbnails, longest side 256 px, at most 256 KiB) and
`.../colors-preview/` (preview poster, longest side 1280 px, falling back to 960 then 640 px until the PNG is at most
2 MiB, original aspect ratio). Built with the notifications `ImageCache` (private 0700 folder with a writer lease,
digest names, no symlinks, size and pixel limits). The source JPEG must lie in the user's cache; anything else, a
missing file or a full folder (16 MiB) gives `thumbnail: ""` (placeholder). The thumbs folder keeps only the files of the
latest catalog; the preview folder keeps only the latest poster.

## A6 theme targets and re-theming

`settings.set colors appThemes.<id>` only writes the store: nothing re-publishes the target (the QML settings provider
ran `nacre-helper app-theme <id> <bool>` after the write; that command writes the store, publishes the target and
refreshes `theme-targets.json`). So `colors.set_target` is the call that re-themes, and `colors.targets` reads the
published `state/theme-targets.json`, falling back to the installed manifest. `status` is what the publisher writes:
`current`, `not-published`, `tool-missing`, `paused` (B0060 asked for `stale`, which does not exist; the first
three are as asked). `label` is the English label of `labelId`. Without the published file every target is
`not-published`.

## A7 file chooser: not done (ask)

No xdg-desktop-portal FileChooser code exists in the repo (the wallpaper picker runs `zenity`) and a portal call needs
a Request/Response signal exchange plus a fake portal in tests, which is not small. Recorded as an ask: a
`colors.choose_image {}` method either via the portal (zbus, `OpenFile`) or the existing zenity route, returning
`{path}` or `{cancelled:true}`. Until then Bead opens an image by argument or wallpaper row.
