# N0070 — Wallpaper picker catalogue

Status: Implemented for Bead B0100; lease-only daemon method.

`wallpaper.catalogue` is lease-only and request-lifetime: the daemon retains no catalogue rows, subscription, worker, or timer after the reply. It returns `{entries: [...]}` with up to 2,048 entries containing `id` (the exact local source path), `kind` (`image` or `video`), `animated`, `title`, `thumbnail`, `preview`, and `active`. `kind` identifies the source container; animated GIFs remain `image` with `animated: true`, matching the source picker's dynamic filter. The existing helper creates thumbnails at most 640×400/256 KiB and previews at most 1600×1000/2 MiB. The thumbnail cache keeps at most 128 entries (32 MiB maximum); preview pairs are pruned with their thumbnail. Paths are returned only from that cache, or as empty strings. The method is advertised with `wallpaper.active`.

For compatibility, `{}` retains eager helper behavior. Optional `ids` accepts at most 128 unique absolute catalogue IDs: `ids: []` enumerates full metadata without decoding videos, generating posters, or materializing thumbnails; nonempty IDs materialize previews only for those validated catalogue entries, preserving the requested batch in the 128-entry cache. Other entries may return empty thumbnail and preview paths. Legacy video poster PNGs use the existing media cache and are not pruned by thumbnail eviction because active/staged presentation ownership is not safely knowable from the cache alone.

The picker subscribes to `wallpaper.active` for the current revision and calls `wallpaper.catalogue` with `{}`. To select, it calls `wallpaper.activate` with `{revision, id}`; the daemon rejects a stale revision or an id absent from the current catalogue, invokes the existing `wallpaper-media select` helper, refreshes `wallpaper.active`, and returns its current `ActiveWallpaper`. Existing `{revision}` calls retain their prior read/confirmation behavior. Selection is guarded by the active revision both before catalogue lookup and immediately before the helper side effect; concurrent selections return `busy`.

The catalogue call runs only on demand through the daemon's bounded helper lane, uses `nice -n 10`, and is bounded to 12 seconds and 8 MiB of output. Selection is bounded to 15 seconds. N0053 startup behavior is unchanged: READY does not wait for wallpaper enumeration or previews; the method becomes available with the active wallpaper topic. Catalog data and selection do not add a settings store; existing picker preferences remain in `wallpaper-picker`.

For a targeted video hydration request only, an entry may also contain the optional `video_predecode` record: the exact extracted PNG poster path, its `WallpaperFileIdentity`, and the source video's `WallpaperFileIdentity`. The daemon emits it only when both files are securely openable and the poster is a stable cached PNG; images, animated images and metadata-only rows omit it. It is an early-decode hint, not authority to publish: clients must retain the existing source, poster, boot, generation and size fences and accept decoded pixels only when the activated pair matches both advertised identities and the exact poster path.

The Arch Fish 4.9 CI fixture pre-seeds and snapshots the user's Fish config files because first launch creates the empty config directory and default `config.fish`; the assertion checks that Nacre's greeting hook leaves those files unchanged.

The source UI uses static/dynamic filters, search over name and path, and carousel/spotlight/hexagon layouts. Its selected item previews while browsing and commits on close; static and motion media share the catalogue, with cached still thumbnails/posters. B0100 owns the Bead UI and parity evidence.

For an explicit targeted video ID, an entry may also carry optional `video_predecode` metadata: the exact cached PNG poster path plus its `WallpaperFileIdentity` and the source video's identity. The daemon emits it only when the requested video, source and poster pass pinned private-file checks; metadata-only, unrequested and image rows omit it. This does not add a method or change activation semantics. Clients revalidate both identities and accept decoded pixels only when the activated motion source, poster path and poster identity match.
