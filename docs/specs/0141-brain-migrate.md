# N0141 — Native Brain migration

Status: implemented; synthetic validation passed. Full desktop CI gates branch delivery. This spec covers U4, the lead-run migration from the Phase 1 Python dry run to the native `nacre-brain migrate` command.

The command classifies with the shared `brain_registry` resolver, seeds `registry.json` from the checked-in vocabulary when needed, and applies `meta`, `inbox`, `archive`, `digests`, `wiki`, `links`, and `index` as independently revertable commits. `all` is equivalent to those steps in that order. Every apply holds both vault locks, checks SHA-256 before replacement, preserves source bodies except planned link-target edits (atomic with moves and in `links`), repairs capture paths, verifies the resulting vault, and restores the pre-step snapshot without committing on failure. Dry run is read-only and reports the mapping, counts, sample header changes, wiki changes, and review flags. Credentials are excluded from discovery and reads.

The registry follows DESIGN.md §16: seeded worlds and areas remain protected; only qualifying unmatched review clusters become proposed areas. Classification rules remain in the shared registry module so writers and migration cannot diverge.

Acceptance uses a synthetic fixture only: approximately 2,000 notes across inbox, checkpoints, decisions, runbooks, projects, devices, personal, wiki, and raw; representative malformed headers, path-shaped body fields, aliases, missing Worlds, inter-note links, capture records, and a decoy under `credentials/`. Tests compare a sequential per-step run with `all`, check dry-run tree identity, idempotence, note-body checksums, link resolution, per-step commit count, lock contention, rollback after injected verification failure, untouched/unread credentials, and a sub-60-second full run.

The Phase 1 Python and verification files under `.lead/ref/` are comparison inputs only, not runtime paths. Retain them for 30 days after the native replacement is trusted, then remove them with the lead's reference cleanup. No real vault is used by tests or this implementation task.

Lead run sequence on the real vault: first `nacre-brain migrate --step all --dry-run --report <private-report-path>` and inspect the report; then run `nacre-brain migrate --step meta --apply`, followed by `inbox`, `archive`, `digests`, `wiki`, `links`, and `index`, each with `--apply`. Preserve and review each commit before starting the next step. Do not use `all --apply` for the lead-visible rollout.

Implementation boundaries: apply requires an initialized vault Git history and a clean, tracked baseline for affected existing note paths (flush pending captures first) and uses a private index for exactly the step paths. It preflights destinations and SHA-256 revisions, retains original bytes/modes for every touched note, registry and state file, rechecks each replacement, syncs changed files and parent directories together at the locked step boundary, and rolls back before any commit on verification or staging failure. Moves repair links in the same commit, preventing an intermediate broken-link tree. A cumulative private move ledger lets `links` repair later notes that still use old paths; mappings whose original paths exist again (for example after a revert) are ignored. Native writers wait on the same vault/capture locks. Unrelated pending paths are preserved; migration refuses to include an earlier uncommitted note body so a later git revert cannot discard it. A push error retains the verified local commit and reports that fact; rerunning retries the push without creating another commit.

The verifier checks exact body bytes against the link plan, original titles and nonclassification headers, curated wiki text outside generated markers, canonical categories or review flags, and the identity of previously resolved links. Existing broken links remain visible; generated pages must introduce none. The derived INDEX is rebuilt explicitly. New reports must be outside the vault and cannot follow symlinks. Credentials, hidden trees and unrelated roots are pruned before traversal. New files use private modes; existing modes are preserved.

The embedded migration page map contains stable wiki filenames, entity roles/aliases, redirects and descriptions only. Classification patterns come exclusively from the shared registry seed/loader. Qualifying Review subjects need three notes on at least two recorded days; migration proposes areas and never creates new worlds or reshapes seed entries. The reference Python used a 14-day archive threshold; this command intentionally defaults to the owner's requested 21 days.

Simplicity review: the native port is larger than 2.5 times the Python reference because it also implements CAS, transactional rollback, native Git integration, zero-write planning, verification and the owner-approved proposal rules. The pass removed unused classification patterns and viewer-only flags from the page map, shared traversal exclusions, validated date parsing and header/list parsing, removed a redundant remapping branch and unused classifier entry point, retained one classifier and one Git guard, and uses one transaction loop for every step. No replacement Python runtime or speculative service/framework is added. The untracked Phase 1 references retain the expiry above.
