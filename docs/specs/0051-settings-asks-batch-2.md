## The ten asks and the answers

| Ask | Answer |
| --- | --- |
| **C1** `bluetooth`, `battery` flags | In the `capabilities` topic. `bluetooth` is true while the `bluetooth` topic is available and lists an adapter (QML `NacreBluetooth.available`); the topic is recomputed when it changes. `battery` is a laptop battery in `/sys/class/power_supply` (`type` is `Battery` and `scope` is not `Device`, so a mouse's battery does not count; UPower's `isLaptopBattery`), probed with the other probes. |
| **C2** clear histories | `clipboard.clear_history {}` -> `{changed}` runs `cliphist wipe` and removes the private files that described the clips (thumbnails, pins, age index). Unlike the existing `clipboard.clear`, which keeps pinned clips for the dashboard, this clears everything, as the QML Privacy page did. `launcher.clear_history {}` -> `{changed}` empties `recent` and `usage` of the `launcher` store (favorites and hidden stay), `changed:false` when there was nothing. |
| **C3** `software-input` store | The store is already published read-only as `settings.store.software-input` (`keyboardLayouts`, `touchpadEnabled`). It is now writable through `settings.set {store:"software-input", key:["keyboardLayouts"], value:string, rev}` ("" resets to the system default; comma-separated XKB ids, at most 160 characters) and `{key:["touchpadEnabled"], value:bool, rev}`. The write is the QML path (`input-preferences`): the file, the managed compositor block, a reload, rollback of both on failure; Hyprland needs a known touchpad identity. Stale `rev` is `stale_revision`; other keys are `permission_denied`. The layout list itself is not a method: it is `/usr/share/X11/xkb/rules/base.lst` (`! layout` section), which Bead may read as QML did. |
| **C4** shortcuts topic | `shortcuts` topic `{health, items: Entities<{key, description, submap?, menu?}>}` (at most 512, `SUPER` first, the helper's order; ids `k0..`) and `shortcuts.refresh {}`. Source: the QML page's `desktop-extras keys` (live compositor bindings merged with the config descriptions). It is read once the compositor is up and again on `shortcuts.refresh`; a config reload is not watched, so Bead calls `refresh` when the page opens. A failed read keeps the last list, stale. |
| **C5** power refresh/fix | `capabilities.refresh {}` -> `{requested}` probes again (touchpad, battery, `powerprofilesctl`, pacman) and republishes `capabilities` (the `power-refresh` adapter). `tools.launch {tool:"power-service"}` runs `pkexec systemctl start power-profiles-daemon` (the `power-fix` adapter when installed); when `powerprofilesctl` is absent it is `unavailable` and Bead opens the packages menu with the C7 route below. |
| **C6** status (read-only) | `system.status {}` -> `SystemStatus`: release revision, service states, failed units, compositor config errors, drifted managed files, Brain sync line, last resource sample, last session event, update-cache age and the AUR review policy provenance (`mode`, `source`, `profile`). It is `maintenance state` (the same collector the Maintenance page called) and `aur-review policy`; strings are cleaned and cut, lists capped. The update list itself is the existing `dashboard.updates` topic. The maintenance *actions* (profile sample, check session, sync, repair portals, restart, rollback) are not part of this unit (see Asks left). |
| **C7** app-to-shell route | No new method: `ui.dispatch {target, method, args}` already forwards to the registered UI provider (the daemon error is `unavailable` while none is). Targets for B0063: see "C7 routes". |
| **C8** add-on install | `tools.launch {tool:"setup"}` opens `nacre setup` in `kitty` (the QML `install-ai`/`install-brain`/`setup` actions are the same command). |
| **C9** `audio.set_default` | Advertised with the other audio methods (needs `wpctl` and the PipeWire socket): `{node}` -> `{changed:true}`. `node` is the PipeWire `node.name` of an `Audio/Sink` or `Audio/Source`; the daemon resolves it with `pw-dump` and passes only the numeric id to `wpctl set-default`. A stream, a video node or an unknown name is `unavailable`, a malformed name `validation`. **Confirmed:** the audio item id Bead sends as `node` must be the `node.name` (the daemon has no `audio` topic and no entity ids; the same convention as `audio.set_volume {target:"node"}`). |
| **C10** `bluetooth.set_trusted` | `{device, trusted}` -> `{changed}`; the id is resolved against BlueZ, then `Device1.Trusted` is set; the same value is not written again. The `bluetooth` topic already carries `trusted`. Needs a published, available BlueZ (like the other `bluetooth.*` methods). |

## `tools.launch {tool}`

One method for the programs the pages start, so no caller can reach a command line. `tool` is a closed set; any other value or
extra field is `validation` (`dispatched:false`). Missing programs are `unavailable` (`dispatched:false`). The program is started
detached (own process group, no stdio, no service-manager socket) and the reply is `{launched:true}`; what happens next is the
program's own, as with the QML `AppLaunch.run`.

| `tool` | Command | QML source |
| --- | --- | --- |
| `audio-manager` | `pavucontrol` | `nacre-shell audio` |
| `connection-editor` | `nm-connection-editor` | `nacre-shell network` |
| `setup` | `kitty --title "Nacre setup" -- nacre setup` | `setup`, `install-ai`, `install-brain` |
| `ai-workspace` | `kitty --class nacre-ai-dashboard --title "Nacre AI settings" -- nacre-ai settings` | NacreAiPage "Accounts, usage and projects" |
| `aur-review-policy` | `kitty --hold --title ... -- <nacre-helper> aur-review policy` | `aur-review-policy` |
| `power-service` | `pkexec systemctl start power-profiles-daemon` (needs `powerprofilesctl`) | `power-fix` |

## Asks left (for Bead, or a later Nacre unit)

- The Maintenance actions (`profile` sample, `session` check, `sync-now`, `repair-portals`, `restart`, `rollback`) and the idle policy
  (`nacre idle`, planned in the registry) have no method: they restart or roll back the desktop and want their own reviewed unit.
- `lock-preview` (`nacre-shell lock-preview`) is a QML-only window; Bead previews its own lock (B0063).
- `settings-backup` / `settings-restore` are `planned` in the registry.
- The keyboard layout list has no method (read `base.lst`; see C3). Add `input.layouts` if Bead should not read host files.
- `capabilities` still sees a touchpad or `powerprofilesctl` change only at start or after `capabilities.refresh`.
- `shortcuts` does not watch the compositor config; call `shortcuts.refresh`.

## Acceptance

Protocol: transcripts replay through the mirror and every call validates (`nacre-protocol` tests, schema and type files exist).
Helper tests with fakes only (temp HOME and `/sys`, fake `wpctl`/`pw-dump`/`cliphist`/programs, a private `dbus-daemon` with a fake

refreshes on request and keeps the last list when a read fails; `system.status` projection of canned documents including hostile
ones; `tools.launch` argv per tool, closed set, missing programs, safe mode. Methods are never advertised in safe mode.
